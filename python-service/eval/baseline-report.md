## 二、检索评测（确定性，不含 LLM，可稳定复现）

`python -m eval.eval_rag` —— 29 条可答用例 + 4 条越界用例，ground truth = chunk 章节标题。

### 生产配置 topK=5 / threshold=0.0

| 指标 | 值 |
|---|---|
| Hit Rate@1 | 89.7% |
| **Hit Rate@3** | **100%** |
| MRR | **0.9483** |
| 平均检索延迟 | 251ms |
| 越界样本平均 top score | 0.4408 |

| 3 | 0.5 | 86.2% | 93.1% | 0.8966 | 258ms |
| 3 | 0.7 | 13.8% | 13.8% | 0.1379 | 260ms |
| **5** | **0.0** | **89.7%** | **100.0%** | **0.9483** | **251ms** |
| 5 | 0.5 | 86.2% | 93.1% | 0.8966 | 271ms |
| 5 | 0.7 | 13.8% | 13.8% | 0.1379 | 217ms |
| 8 | 0.0 | 89.7% | 100.0% | 0.9483 | 321ms |
| 8 | 0.5 | 86.2% | 93.1% | 0.8966 | 260ms |

**结论**
- threshold=0.0 才是正确生产取值；0.5 会掉 6.9 个百分点，0.7 直接崩到 13.8%

- 越界样本平均 top score 0.4408，是阈值标定的依据：阈值设在 0.44 附近可把越界查询挡在门外，
  但会牺牲 6.9 个百分点的召回，因此当前选择保持 0.0

## 三、生成质量评测（LLM-as-Judge，含随机性）

`python -m eval.eval_answer --mode=rag|react` —— 30 条用例：
政策问答 10 + 业务工具 12 + 越界拒答 4 + 口语化 4。
裁判打三个维度：faithful（引用忠实度）/ refused（正确拒答）/ tool_correct（工具选型）。

### 稳定性（各跑 3 轮，`python -m eval.eval_stability`）

| 链路 | 指标 | min | **中位** | max | 波动 |
|---|---|---|---|---|---|
| rag | 成功率 | 30/30 | **30/30** | 30/30 | 0 |
| rag | 引用忠实度 | 86.67% | **90.00%** | 90.00% | 3.3pt |
| rag | 工具选型准确率 | 100% | **100%** | 100% | 0 |
| rag | 越界拒答率 | 100% | **100%** | 100% | 0 |
| rag | 平均延迟 | 2099ms | **2206ms** | 2296ms | 197ms |
| react | 成功率 | 30/30 | **30/30** | 30/30 | 0 |
| react | 引用忠实度 | 83.33% | **83.33%** | 90.00% | 6.7pt |
| react | 工具选型准确率 | 100% | **100%** | 100% | 0 |
| react | 越界拒答率 | 75% | **100%** | 100% | 25pt |
| react | 平均延迟 | 2110ms | **2148ms** | 2194ms | 83ms |

### 两条链路对比

| 维度 | rag（固定管线） | react（LangGraph 自主规划） |
|---|---|---|
| 成功率 | 30/30 | 30/30 |
| 引用忠实度（中位） | **90.0%** | 83.3% |
| 工具选型准确率 | 100% | 100% |
| 越界拒答率（中位） | 100% | 100% |
| 平均延迟 | 2206ms | 2148ms |
| 工具调用 | 固定管线，业务工具由模型按需触发 | 模型自主决定调哪些、调几次 |
| 政策类问题 | 检索在管线内部完成 | 显式调用 searchPolicyKnowledge |

### 解读
1. **成功率 100% 稳定** —— 评测脚本已修复 event loop 与致命错误问题，链路可靠。
2. **引用忠实度存在 3~7 个百分点随机波动**（judge 为 LLM，temperature=0 也非完全确定）。
   → 任何改造对比必须**同配置跑 3 次取中位数**。
3. **react 的越界拒答率波动 25pt**，根因是越界用例只有 4 条，样本粒度太粗
   （错 1 条即掉 25%）。要提高可信度需把越界用例扩到 15 条以上。
4. **react 忠实度略低于 rag**，符合预期：自主规划多一次工具调用环节，
   引入更多可偏离参考要点的机会。

### 三条硬性规则
1. **只认可重复 3 次的中位数**，单次结果不作数。
2. **检索类指标是确定性的**（纯向量 + 阈值，无 LLM），单次即可对比，
   但报告里要标明跑了多少组参数。
3. **任何一轮出现 `aborted=true` 的结果一律作废**（说明中途有致命错误，
   样本不完整）。`summary.executed` 必须等于 `summary.total`。

## 五、已知限制

1. **知识库只有 6 个 chunk**，检索指标的绝对值不可与公开数据集横向比较；
   也意味着 BM25/Rerank 的对比样本量不足，需要扩充评测语料后再评估。
2. **越界用例仅 4 条**，拒答率指标粒度太粗，波动敏感。
3. **检索评测的 ground truth 是章节标题**，粒度较粗（一章一 chunk），
   测不出同章节内的细粒度区分能力。
4. **生成评测未覆盖多轮对话场景**，长会话下的记忆/上下文能力尚无数据支撑。
5. 忠实度受裁判模型影响，DeepSeek 换版本后基线会变，需重新测量。
